**90-Day Cloud Engineering Journey**

## Objective

Establish a clear mental model of cloud computing before deploying infrastructure.
Focus was on understanding **service models, responsibility boundaries, and business value** rather than immediate hands-on execution.

---

## Key Concepts Learned

- Cloud computing replaces **infrastructure ownership** with **on-demand access**
- Cloud service models define **who manages what**
- Primary benefits include scalability, cost efficiency, operational speed, and reduced hardware overhead

Service Model Overview
- **IaaS:** Full control over compute, storage, and networking
- **PaaS:** Application deployment without server management
- **SaaS:** Fully managed software accessed via browser or API

---

## Deliverable

**Cloud Service Model Comparison Framework:**
- Created a responsibility vs control comparison for IaaS, PaaS, and SaaS
- Build a reusable decision framework to guide future architecture choices

**AWS Resources:**
- No cloud resources deployed

---

## Engineering Insight

The cloud is not abstract or "magical."
It is **distributed infrastructure optimized for scale, availability, and cost efficiency** - and understanding responsibility boundaries is critical to using it safely and intentionally.
